# Public evidence agents

Four bounded batch roles: official page/link discovery; public channel/article monitoring; open-model extraction plus PDF/XLSX/OCR readers; grounding/date/conflict verification. Only public sources, no account/subscriber/address queries, hosted inference APIs or paid server. Daily at 04:47 UTC; scheduled GitHub runs may be delayed or disabled after repository inactivity. Free standard public runners are subject to GitHub's terms and availability.

Qwen2.5-1.5B-Instruct Q4_K_M runs on CPU via llama.cpp bound to localhost. Model/runtime URLs, immutable revision and SHA256 are pinned in model-lock.json. Model Apache-2.0 and llama.cpp MIT licenses apply; binaries and weights are downloaded during jobs, not redistributed in this repository. Setup verifies hashes. A synthetic quality gate must pass before live processing; controls and prompt examples are never published as address records. The model has no tools, shell, tokens or ability to change source code.

`sources.json` is a reviewed URL directory, not a queue/address fixture. Discovered links are proposed separately; bot/private links are excluded. Telegram preview title changes stop collection. Community ownership is not inferred from a similar handle. Only dated, individually linked posts or articles with machine-readable publication dates are considered. Telegram text and bounded linked PDF/XLSX/image attachments are supported; not every social network or attachment format is readable. No login or protection bypass. Existing official document collection remains separately operational in public-source-cache.

Every accepted suggestion needs an exact verbatim sentence, explicit settlement/community, street and listed houses or literal whole-street/whole-settlement wording, operator binding, source URL and publication time. The model cannot expand house ranges. Statements about outages, uncertainty, old assignments, future-effective changes, questions and ungrounded claims abstain. Seven-day publication-age cap cannot be extended by fetching the same post again. New ambiguous neighborhoods or incomplete location references abstain rather than invent boundaries. Mirrors are not counted as independent confirmation.

`manifest.json` carries `enabled`; false disables all suggestions. New versions start in shadow mode until controls and live output are reviewed. No fabricated records should be added to this file to demonstrate growth. Client checks exact operator/region/community/locality/street/house and all conflicting matching scopes locally. Application implementation and user addresses stay out of this public repository. Public evidence always stays provisional; it never overrides official exclusion/ambiguity or a user's correction.

One-command rollback: `python public-evidence/disable.py`, then commit/push its two control-file changes to main. This sets `enabled:false` in sources.json and manifest.json, preserving schemaVersion/generatedAt/records. The next job preserves disabled mode. Online clients revalidate on the next public-queue lookup (at most 15 minutes while actively used); already offline devices cannot receive a remote switch and stop using the suggestion at its original expiry. Stale/unreachable manifests cannot issue a fresh suggestion. A later valid official lookup replaces a provisional queue.

The original three-channel pilot was not nationwide social coverage; the version-two directory below expands it. Adding a reviewed source requires only configuration, not hardcoded queue facts. Report and discoveries record actual errors and collection counts. Success of the pipeline does not establish real coverage growth; use an actual app address audit for that.

## Version two: targeted sources and historical research

The directory now includes municipal roots and their linked public channels in the four target oblasts, plus a reviewed local section-roster publication. Free DuckDuckGo HTML discovery proposes sources; exact locality relevance rejects unrelated results. Leads require source/geographic review before activation. Public Telegram pages are paginated with a 180-day research window, per-source page limits, explicit earliest-date/stop-reason metrics and a persisted backfill cursor. A first run reaching a page limit has not scanned six months. Municipal index readers follow dated electricity-related articles. Historical candidates are separate from the app manifest. Search queries use public locality/source terms, never user account/EIC identifiers or live user-address requests.

Schema 2 supports literal house ranges, explicit parity/exclusions and postal previous-name matching on the phone. Compound corner endpoints identify those endpoints only; plain-number houses strictly inside the numeric interval can match. No suffixes, parity or missing buildings are invented. Unsupported exception/entrance qualifiers abstain. A section roster is split at queue headings and every locality marker; unrecognized neighboring villages cannot inherit the previous city's identity. Source quote, queue heading and geographic context remain distinct evidence. No QA target supplies production queue facts; the reader extracts all supported streets in a source.

Older sources can activate a suggestion only with an explicit currently active publisher period. Both clients and collectors validate the literal calendar dates, original publication, observation age and end date. Source periods longer than 370 days, future/expired periods, stale observations or contradictory records abstain. This is not a renewal of an old post's date: source publication remains unchanged and displayed. A fetch does not extend the publisher's period. Offline expiration remains bounded by the saved expiry. Other historical messages stay leads under the original seven-day rule. A successful reread replaces old claims from that publication; an access failure cannot renew them.

Schema-1 clients ignore the schema-2 manifest safely. Official/manual/direct/cache lookup remains independent. Collectors cap the manifest as a complete dataset; exceeding the size budget fails rather than silently removing potentially contradictory claims. The 13 functional model controls now include a positive literal range and negative future-effective notice; separate deterministic controls check cross-locality leakage, exclusions, search relevance and individual publication dates. These are functional controls, not a measured real-world precision score.

## Linked-document monitoring

Reviewed news/press indexes in `sources.json.documents` are scanned for recent topical articles and PDF/XLSX links on explicitly reviewed operator hosts. The reader checks document signatures, bounded page/cell/text counts, content hashes and final redirect hosts. Article dates using `time.content-date` are supported; generic sidebar/footer dates are ignored. Four articles, two operator landing pages (one hop only) and three documents per index bound each scan. The PDF name is discovered from links on every run, never derived from a season or fixed in code. Errors and actual inspected counts remain in `report.json.agents.documents`.

Document observations are research candidates only and contribute **zero runtime records**. `linkedFromPublishedAt` dates the linking article; `documentPublishedAt` remains unknown until independently established. A recent news article must never renew an old PDF or turn its contents into a current queue assignment. The app manifest and current official/manual/public matching rules are unchanged. A downloaded document still needs a grounded, current address/scope reader before activation. Public address services returning 403 are not bypassed or copied from search snippets into the manifest.

## Live public address directory observations

A separate standard Chromium reader follows published street links from reviewed locality directories. It handles only whole-street `/grafik/locality/street` pages whose address heading, displayed queue label and current daily graph date agree. The complete locality index is checked for house-selection aliases, numeric/partial selectors and combined street labels before the scan window is chosen; these cannot conceal a contradictory street scope. House-selection pages, qualified/partial streets, conflicting matches, old dates and changed geography abstain. Successfully enumerated indexes retract removed or newly ambiguous observations. Source URLs and all queues are extracted anew; configuration contains no house numbers, queues or season file names.

Record version 3 keeps the observation timestamp separately from `publishedAt:null`. It does not claim a publication date or an operator-confirmed house connection. APK65 validates the URL/title/queue/date/geography together and displays the street scope and observation time. APK64 safely ignores these records while retaining supported version-two records. Observations expire within 12 hours and at the Kyiv day boundary. Failed reads cannot renew them. Manual corrections and official findings keep their priority.

The directory workflow uses free standard public GitHub runners every six hours. **Current limitation (2026-10-29):** this source returns HTTP403 from both tested GitHub runner networks, including a normal browser. A local standard Chromium read succeeded. Therefore hosted refresh is not yet operational for this source, and current observations must not be presented as permanent coverage growth. The workflow reports the failure and leaves the previous manifest untouched. After expiry the app withdraws the observation. No paid relay, protection bypass or permanent server was introduced.

A reproducible refresh from a network where the public pages are readable is `SVITLO_BROWSER_BIN=/path/to/chromium python public-evidence/directory/collect.py` after installing the pinned Playwright/BeautifulSoup dependencies. This reads every supported street page within each scan budget, never individual user queries. For large locality indexes the 80-street window rotates via `directory-state.json`; the report states candidates, inspected pages, limits, cursor and errors. This is not complete regional or city coverage.
