# Public evidence agents

Four bounded batch roles: official page/link discovery; public channel/article monitoring; open-model extraction plus PDF/XLSX/OCR readers; grounding/date/conflict verification. Only public sources, no account/subscriber/address queries, hosted inference APIs or paid server. Daily at 04:47 UTC; scheduled GitHub runs may be delayed or disabled after repository inactivity. Free standard public runners are subject to GitHub's terms and availability.

Qwen2.5-1.5B-Instruct Q4_K_M runs on CPU via llama.cpp bound to localhost. Model/runtime URLs, immutable revision and SHA256 are pinned in model-lock.json. Model Apache-2.0 and llama.cpp MIT licenses apply; binaries and weights are downloaded during jobs, not redistributed in this repository. Setup verifies hashes. A synthetic quality gate must pass before live processing; controls and prompt examples are never published as address records. The model has no tools, shell, tokens or ability to change source code.

`sources.json` is a reviewed URL directory, not a queue/address fixture. Discovered links are proposed separately; bot/private links are excluded. Telegram preview title changes stop collection. Community ownership is not inferred from a similar handle. Only dated, individually linked posts or articles with machine-readable publication dates are considered. Telegram text and bounded linked PDF/XLSX/image attachments are supported; not every social network or attachment format is readable. No login or protection bypass. Existing official document collection remains separately operational in public-source-cache.

Every accepted suggestion needs an exact verbatim sentence, explicit settlement/community, street and listed houses or literal whole-street/whole-settlement wording, operator binding, source URL and publication time. The model cannot expand house ranges. Statements about outages, uncertainty, old assignments, questions and ungrounded claims abstain. Seven-day publication-age cap cannot be extended by fetching the same post again. New ambiguous neighborhoods or incomplete location references abstain rather than invent boundaries. Mirrors are not counted as independent confirmation.

`manifest.json` carries `enabled`; false disables all suggestions. New versions start in shadow mode until controls and live output are reviewed. No fabricated records should be added to this file to demonstrate growth. Client checks exact operator/region/community/locality/street/house and all conflicting matching scopes locally. Application implementation and user addresses stay out of this public repository. Public evidence always stays provisional; it never overrides official exclusion/ambiguity or a user's correction.

For rollback, set `enabled:false` in sources.json and manifest.json, preserving schemaVersion/generatedAt/records. The next job preserves disabled mode. Online clients revalidate on the next public-queue lookup (at most 15 minutes while actively used); already offline devices cannot receive a remote switch and stop using the suggestion at its original expiry. Stale/unreachable manifests cannot issue a fresh suggestion. A later valid official lookup replaces a provisional queue.

The current three initial channels are a pilot, not nationwide social coverage. Adding a reviewed source requires only configuration, not hardcoded queue facts. Report and discoveries record actual errors and collection counts. Success of the pipeline does not establish real coverage growth; use an actual app address audit for that.
